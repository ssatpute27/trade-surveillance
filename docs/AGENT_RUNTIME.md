# Local investigation service

Run `.venv/bin/uvicorn app.server:app --host 127.0.0.1 --port 8767` from the repository root. Open `/population.html`. Do not use the old static HTTP server for the live app.

The source database is read-only. Durable jobs, report revisions, retrieved evidence, human actions and email outbox records live separately in `data/agent.sqlite3`. Four workers claim queued runs atomically. Incoming case events deduplicate. When the full alert feed is enabled, newly eligible source cases are ingested every ten seconds. Existing runs and human decisions are not reset.

The live agent uses Responses tool calling, hosted File Search over eight synthetic bank policy PDFs, and Embeddings search over 4,816 source communications. Markdown policy documents are a setup fallback if no rendered PDFs exist. Every case must pass essential checks and family-specific controls before final draft generation. Initial assessments, purposes of tool calls, returned source IDs, depth promotions and validation results are audited. No hidden chain of thought is presented.

Reports are schema-validated, checked for exact retrieved quotes, and independently reviewed for support by a model. These checks are fallible. Failed repair, unavailable evidence or exhausted budgets preserve work for human attention. Unavailable information does not prove absence. Recovery marks interrupted investigations as requiring attention instead of silently restarting them.

Analyst decisions are separate records. Request more evidence creates the review event, preserves the prior version, and queues the next revision in a single transaction. Reviewer notes are questions, never source facts.

Email is configured through the local Email setup form. A validated report and a unique outbox entry commit together. Gmail uses STARTTLS on port 587 with certificate verification using certifi. Credentials stay in ignored mode-0600 local configuration. Missing credentials block delivery; authentication failures wait for configuration changes. Pre-submission failures allow at most three attempts. Ambiguous submissions become `delivery_unknown`, requiring a Sent-mailbox check before manual retry. SMTP acceptance is not verified inbox delivery.

The Evaluation & audit view computes real metrics from stored runs and offline synthetic grading keys. Those keys are not imported by the agent or its tools. Recorded cases are integrity-checked read-only snapshots of actual live runs. Replay creates no jobs, decisions, API calls or emails.

This application binds to loopback and requires the local UI header for mutations. It is a single-user synthetic demonstration, not a production multi-tenant security or compliance system.

## Timeline, prior cases and recorded calls

Agent controls v4 add mandatory `reconstruct_timeline` and `retrieve_prior_cases` calls after the initial assessment. Cases with eligible recordings also require `transcribe_calls`. The 24-call budget includes these checks. Existing case revisions and dispositions are preserved; new evidence is used only in subsequent investigations.

`reconstruct_timeline` merges linked orders, eligible fills, customer instructions, venue submissions/cancellations and authorized account-scoped communication/access events. Timestamps and fill ingestion respect the case cutoff. The extract is bounded to 160 events with an explicit truncation flag. Account proximity is not an order/security link or evidence of causation. The Trading tab renders the retrieved sequence; Sources retains the exact cited extract.

`retrieve_prior_cases` filters earlier completed cases by alert family and authorized scope before sending any candidate text to OpenAI. It uses the configured Embeddings API model (`text-embedding-3-small`, 512 dimensions by default) to rank cosine similarity to the model's search query; lexical overlap and recency break ties. It returns up to three historical comparisons with semantic scores and model metadata. Scores measure relevance, not misconduct likelihood or decision confidence. Unchanged candidate embeddings are cached locally by content, identity, model and dimensions; the query is embedded for each search. Embedding failures are explicit rather than silently replaced by keyword ranking. Traces include Embeddings API calls and the local audit records cache/search counts.

Actual local decisions must predate the current case's start, belong to authorized account scope, and come from human review records. Agent recommendations are never presented as prior dispositions. The demo archive additionally contains eight explicitly authored fictional reference cases, one per family, dated before the population. Unscoped archive records are allowed only when labeled as authored fictional references. These are analogies only, not real analyst history, current-case evidence or evaluation answer keys. Future, inaccessible, current-case and unrelated-family records are excluded. Existing assessments are unchanged; new searches use semantic ranking.

`transcribe_calls` verifies case/account permissions, historical archive availability and the audio SHA-256 before opening a recording. It calls OpenAI Audio Transcriptions with `whisper-1`, verbose JSON and segment timestamps. This model was selected for timestamp support. Transcripts are cached by audio hash plus model; cache reuse is audited distinctly from a fresh API call. The authored speech script is never passed to transcription. Transcripts are embedded using `text-embedding-3-small` and become searchable alongside messages after retrieval in the run.

Six demonstration recordings re-enact existing synthetic evidence for six incoming-alert samples. They are created using OpenAI `gpt-4o-mini-tts` with an AI-generated voice and explicitly disclosed in the UI and recording metadata. Their historical recording timestamps are fictional scenario metadata; actual synthesis/transcription processing times are preserved separately. `derived_from` identifies the original source. The model must not count the re-enactment and original as independent corroboration or infer speaker identity. Transcription can contain errors; analysts can play the recording and inspect timed segments in Sources. No production call archive or audio upload facility is claimed.

Prepare demo assets explicitly with `.venv/bin/python -m scripts.prepare_investigation_archive`. This makes paid TTS calls only for recordings not already in the manifest. Files live in `data/investigation_archive`; no directory is statically exposed. `/api/cases/{case_id}/audio/{recording_id}` enforces case scope and content integrity before serving a recording. Recorded-case replay remains read-only and makes no API calls.

### Conversational demo audio

The current `conversational-v2` assets speak only natural desk dialogue, with no spoken training/disclosure introduction. The player carries a compact “Demo audio · AI-generated voice” label; full origin and derivation remain under Recording provenance. Speech scripts preserve source quantities, security and account, and do not invent an explanation or independent corroboration. Previous audio files, hashes, transcripts and case revisions remain accessible. Each changed recording receives a new ID and hash, so its transcript is obtained from the new audio rather than reusing the older introduction-bearing transcript.

The case polling loop leaves an unchanged case DOM intact and defers case updates while audio plays. This prevents the four-second workspace refresh from resetting playback. Audio metadata loads before playback and a direct recording link is available.

The latest `conversational-v3` demo recordings use OpenAI's Marin voice with relaxed phone-call prosody, softer delivery and natural pauses. They retain the same source-based dialogue and omit spoken demonstration introductions. Prior voice versions remain preserved under their original recording IDs and hashes.

Controls v4.1 tighten interpretation of closing-price evidence: a valuation-related comment plus late-day concentration is an investigative lead, not an explicit instruction to move a price. The investigator and independent support reviewer must distinguish quoted wording from a price-influence hypothesis and must not claim measured causal price impact from this dataset. A development quality note preserves the earlier demo draft's overstatement in history; a new revision runs under the tightened guidance.

## Hosted Code Interpreter (controls v5.2)

`analyze_execution_patterns` is a custom investigation tool backed by actual OpenAI Responses calls with the hosted `code_interpreter` tool, using the configured model. It is mandatory for closing-price, spoofing/layering and front-running families, available to other cases when useful, and exposed only after trade and timeline retrieval. The default run deadline is 360 seconds; the tool uses bounded hosted calls and at most one missing-file repair response.

The backend exports only linked orders, eligible fills (execution and ingestion before cutoff), as-of venue orders, applicable exchange sessions and permitted timing markers. Later cancellations are redacted. It submits no evaluation keys, unrelated accounts, email credentials or full database to the container. Inputs are capped at 5,000 fills/venue orders and 5 MB per artifact. The model executes the supplied versioned pandas and plotting recipe against the real uploaded JSON to produce `analysis.json` and `execution_pattern.png`. The parent model’s narrative query cannot replace case scope or normalize order IDs. Minute bars use minute-sized datetime widths. File transfers refresh their shorter request budgets; cleanup has a separate five-second budget per resource.

Numeric outputs must match a separate local implementation: fill count, total/buy/sell shares, USD-cent notional, session final-five-minute shares/percentage, venue-order cancellation counts/percentage, and every occupied minute bucket in Eastern time. These reference answers are not supplied to the hosted model. Wrong numbers do not enter the investigation evidence. Required-tool failures result in manual attention. Case-share percentages are never described as market-volume participation, and venue-order cancellations are not parent-order cancellations. No causal price impact or intent can be established from this chart.

After successful checks, the exact input JSON, generated calculation JSON and PNG are saved under `data/analysis_artifacts/<run_id>/`, with SHA-256 names and evidence-linked metadata. Their case/revision-scoped route checks snapshot authorization and file hashes. Files without a validated evidence snapshot cannot be served. OpenAI response/container/file identifiers, input hash and executed Python are recorded in the audit. Downloaded chart pixels still require visual review; numeric agreement alone does not prove the chart is correct.

Owned temporary uploads and containers are deleted after local retention; cleanup failures are audited, and hosted containers otherwise expire. Older reports and recordings remain preserved. Trading displays the chart and checked measurements above the chronological timeline. Sources includes an Execution chart shortcut, the cited numeric evidence and artifact links. Investigation shows hosted execution and validation events with expandable Python code. Recorded-case replay causes no new hosted execution.

## Evidence follow-up and quality review (controls v6.1)

Analyst requests can include a document title, source reference and pasted excerpt. These are distinct from the review note: the note is a question; the document becomes unverified citable evidence. The review, new revision and immutable submission commit in one transaction. `read_submitted_evidence` is mandatory when a revision or its same-case ancestors have submissions. Later submissions never appear in earlier revisions or another case. They carry their actual receipt time, hash and authenticity limitation; original source cutoffs stay fixed. A submission does not guarantee a changed recommendation.

The Assessment journey shows the prior draft, analyst question, new source IDs, provisional initial assessment and final recommendation from persisted records. It reports retained assessments honestly. History preserves the original versions. A first-load race that could omit history was corrected. Sources displays late-submission provenance separately from the original cutoff.

Communications retrieval now surfaces unavailable notices and redacted access denials without requiring embeddings. Available messages still use hybrid search. New coordinated-trading runs require communication search. Older evaluations use their recorded mandatory checks, rather than retroactively applying new requirements.

`evals/quality_baseline_v5.json` and `docs/QUALITY_REVIEW.md` preserve the original 42 disagreements and all original labels. Evaluation exposes expected labels, missing source keys, diagnostic flags and control-version cohorts. Flags are review leads, not adjudicated causes. Runs with later submitted evidence are excluded from original-label agreement, because the original scenario key does not cover the new evidence. This is not a claim of improved decision accuracy.

Support-review rejections must identify exact claims in the current draft. Contradictory or untraceable reviewer feedback holds the run; it never automatically approves it. Provisional draft candidates and support-review feedback are saved for inspection. Candidate drafts are not analyst-ready reports.

Current workflow routing remains local: Request more evidence queues another investigation; Escalate records the analyst action and places the case in Escalations; Mark reviewed records completion. Owner assignments and closure reasons are supported by the manager workflow below; external desk/records-owner email dispatch remains unconnected. `demo_verification` can only request a follow-up and labels the actor Demo workflow verification; it cannot record a final disposition.

## Analyst escalation PDF and manager handoff

An explicit analyst Escalate action commits the decision and an immutable escalation snapshot/outbox packet in one transaction. The snapshot includes that revision's report, retrieved evidence, case scope and analyst note. `generate_escalation_pdf` then produces a cited PDF using ReportLab; this application tool is audited and does not invoke the model or select an analyst disposition. The document keeps the agent recommendation separate from the analyst escalation, includes available hash-verified execution charts, and preserves exact source excerpts and recording/submission provenance.

Packets are retained under `output/pdf/escalations`, using content hashes. Downloads require the matching case and packet and verify the file hash. The PDF and manager-email statuses appear in Assessment under Surveillance manager handoff. Preview escalation PDF is read-only: it records no decision, queues no packet and sends no email. The standalone sample at `output/pdf/escalation-summary-preview.pdf` is clearly marked as a preview.

`SURVEILLANCE_MANAGER_EMAIL` is separate from the analyst notification address. The current user-authorized demo manager is sheenadesai27@gmail.com. On escalation, the background worker sends that manager a distinct email with the PDF attached, the analyst note and a case link, using the existing configured sender. Review-ready analyst notifications remain separate. No live case was escalated merely to test this feature.

A PDF failure preserves the escalation and offers Retry PDF generation without another review action. Manager delivery waits for a ready, intact PDF and valid sender/recipient configuration. Pre-submission connection failures retry at most three times; authentication failures wait for credential correction. Ambiguous SMTP submissions and interrupted sends become delivery_unknown and are never automatically retried. A successful SMTP submission is labeled accepted by email server, not verified inbox delivery. Recovery resumes interrupted PDF generation, while preserving uncertain delivery states.

## Manager review and ownership (controls v7)

Escalate now opens a persistent manager case owned by the configured surveillance manager, in addition to producing the PDF and manager email. The email links directly to the Manager review case tab. Escalations shows current ownership, status and the latest revision. This remains a single-user local demonstration: the manager workspace explicitly identifies its local role, not an authenticated organizational identity.

The manager can return a case for evidence with a responsible person/team, assign one deeper investigation with an owner, approve closure with a selected reason and rationale, or refer it to Compliance investigations or Legal. Referrals record a local destination and owner; they do not dispatch external email or make a regulatory filing. Each action has an immutable history entry and a case audit event. Optimistic version checks prevent stale actions; request IDs deduplicate retries, including concurrent assignment attempts.

Return for evidence sets Awaiting evidence and starts no agent run. Evidence requests provides the submission entry point. A supporting document is required to resume a supervised case; submitting it creates one new revision and carries forward the manager question. The original report, cutoff and submission provenance remain preserved.

Assign deeper investigation creates one queued revision with required_depth=deep. The investigator enforces deep promotion even for otherwise lightweight size cases. Completion returns the draft to analyst review, not automatic closure. After checking it, the analyst uses Return to manager (the existing escalation handoff), producing an updated PDF and manager email for that new revision. Analysts cannot bypass supervisory closure using Mark reviewed on a managed case. Interrupted jobs retain their evidence and return for analyst attention.

Manager-approved closure moves the case to Completed cases with its selected reason, rationale, owner and decision history. Closed cases cannot be changed through manager actions, and synthetic demo-event delivery cannot bypass the supervised workflow. Historic escalation cases acquire their initial manager state without sending another email.

Verification: unit and concurrency checks cover the complete evidence-return/assignment/analyst-return/closure path, referral recording, stale versions, immutable decisions and deduplication. Browser verification used tmp/manager-workflow-verification with copied existing case data, disabled SMTP and disabled agent workers. Its completion fixtures test workflow transitions, not model accuracy. No production case was escalated, closed or emailed for these checks.
